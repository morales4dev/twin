## Why

Twin's Agent OS is already Cursor-ready in canon (`ai-specs/AGENTS.md`, standards, project skills, thin root `AGENTS.md`), but the delivery layer is Copilot-only. Cursor does not load `.github/skills/` or `.github/prompts/`, so `/opsx-*` and OpenSpec CLI skills never fire here. The repo is now used in Cursor and must keep VS Code + Copilot working too.

## What Changes

This change is Agent OS delivery and discovery only. It does **not** change visitor-facing twin behavior. Specs are skipped (`skip_specs: true`).

- Keep every Copilot surface as-is: `.github/skills/openspec-*/SKILL.md`, `.github/prompts/opsx-*.prompt.md`, `.github/agents/openspec.agent.md`, and `openspec/config.yaml` `githubCopilot.cloudAgent: false`.
- Add the Cursor delivery layer beside Copilot via the official OpenSpec 1.12.0 path (`openspec init --tools cursor`), not a hand-copy: `.cursor/skills/openspec-*/SKILL.md` and `.cursor/commands/opsx-*.md` for the core workflows (explore, propose, apply, update, sync, archive).
- Point the constitution at dual-tool discovery: Cursor agents load `.cursor/skills/`; Copilot agents keep loading `.github/skills/`. Project skills stay in `ai-specs/skills/` and load on demand.
- Tighten `openspec/config.yaml` design rules so OpenSpec CLI skills are named in both IDE paths. Do not move those skills into `ai-specs/`.
- Keep one constitution. Root `AGENTS.md` stays the thin always-apply pointer. Do not paste `ai-specs/AGENTS.md` into `.cursor/rules/` or a second constitution.
- Leave MCP alone. Do not add `.cursor/mcp.json` or `.vscode/mcp.json`. Context7 stays “resolve ID + pass the pin.”
- Update operator docs only where they go stale: README should say Cursor uses the same `.vscode` launch config and interpreter. Do not dump the constitution into README.

**Non-goals**

- Product capability specs under `openspec/specs/` (existing `prompt-firewall` and `scope-classifier` stay untouched; none will be invented).
- Visitor-facing Gradio chat, `backend/src/**`, pins, or tests.
- Removing or relocating Copilot files (Cursor-only switch is out of scope).
- Moving OpenSpec CLI skills from `.github/skills/` into `ai-specs`.
- A second constitution, always-apply `.cursor/rules/*.mdc` that paste `ai-specs/AGENTS.md`, or optional glob rules that only point at standards (later, if wanted).
- `.cursor/mcp.json`, `.vscode/mcp.json`, hosted MCP URL pins, CI, live MiniMax E2E.
- Changing `githubCopilot.cloudAgent` or adding Copilot cloud-agent files.
- Archiving this change (archive only after a later explicit user request).

No **BREAKING** API or Gradio UX change.

## Capabilities

### New Capabilities

- None. This change does not introduce product behavior. `skip_specs: true` is set on the change.

### Modified Capabilities

- None. Existing `prompt-firewall` and `scope-classifier` requirements do not change.

## Impact

- **Agent OS:** `ai-specs/AGENTS.md` (dual-tool skill paths). Root `AGENTS.md` stays thin. Project skills stay under `ai-specs/skills/`.
- **Cursor delivery:** new `.cursor/skills/` and `.cursor/commands/` generated by OpenSpec.
- **Copilot delivery:** `.github/skills/`, `.github/prompts/`, `.github/agents/` kept; `githubCopilot.cloudAgent: false` kept.
- **OpenSpec:** change metadata `skip_specs: true`; design rules in `openspec/config.yaml` name both skill roots.
- **App code:** no required change to `backend/src/**`.
- **Dependencies:** no pin changes.
- **Docs:** README Run/launch note if it still mentions VS Code only.
- **Out of impact:** visitor chat, firewall/classifier specs, live MiniMax E2E, MCP config, Copilot cloud agent, CI.
